## Remaining work and compatibility

- `asura-keoa`: the GitHub `release` environment now allows only branch `main`. The workflow requires new `RELEASE_APPLE_*` environment secrets and fails closed until they are supplied. An owner must migrate the credentials, remove or revoke the old repository-wide `APPLE_*` secrets, set appropriate review and main/workflow protections, restrict release-tag creation to release owners, and prevent tag updates and deletion. Secret values cannot be retrieved for automatic migration. See [release instructions](../macos-release-rehearsal.md).
- `asura-oe2a`: CDP native/managed copies and parsing are bounded, but Chromium allocates its original full-tree response before the callback. Trusted semantic targeting is retained. Rows 20/24/30/45 share this remaining upstream limitation.
- `asura-poul`: future upgrades preserve browser-history opt-outs. Migration 21 already erased the provenance of older choices, so historical opt-ins cannot be reset safely without user review.
- `asura-4j2j`: a separate boot-integrity handoff issue remains: the native VM reopens image paths after managed verification. The boot-cache fix prevents outside host-file mutation; it does not claim immutable descriptor transfer into the VM.
- `asura-3hl3`: the adjacent managed runtime metadata overwrite now uses descriptor-relative replacement. Native rootfs/disk operations and later state pathname mutations still require review; this separate issue remains open.
- `asura-z5aa`: isolated server databases use a separate service VM. Guest-local certificate/wallet options fail before worker launch instead of acquiring host-file authority. Bounded guest material import remains follow-up work.
- Kubeconfig credential sources require a fresh explicit review. Approval binds source paths and configuration; credential files may rotate at those approved paths without renewed review. Git worktree/LFS image previews require Python 3 in the connection environment and fail closed if it is unavailable. Discovered Prometheus services require explicit selection.

## Validation

Full repository gate `./scripts/check.sh --full` passed using the pinned .NET SDK 10.0.303. All 28 managed test projects completed: 11,978 passed, 19 skipped, zero failed. The skipped integration tests require explicit runtime payloads, external services, native-vault opt-in, or private test configuration. Locked restore, dependency audit, deterministic formatting, the Release build (zero warnings/errors), Python regressions, Go tests/race checks, and native networking/macOS probes passed.

The vendor binding suite separately passed all 29 tests. The final targeted regression run passed 1,911 tests across core, agent, runtime, terminal, Kubernetes UI and browser-history/migration paths; these overlap the full-suite total.

Focused infrastructure checks passed all 120 selected tests, and the lock-concurrency regression passed 10 repeated runs. The private release-source archive regression passed both tests and failed against the old code.

Native CEF rebuilt successfully from the verified source archive and passed the profile, authentication, cookie, popup and CDP probes. The retained gzip/CDP budget regression passed twice against that artifact: a compressed 16 MiB-plus response stopped at the 16 MiB decoded limit, and a 9 MiB CDP response returned a small error. Shell validation also passed for all 30 release workflow run blocks.

No live release signing, notarization or publication was performed. The external change was creation of a main-only GitHub release environment; existing secret values were neither read nor removed.

## Scope limits

Browser response filtering limits delivered decoded bodies and resource counts. It does not limit image codec pixel allocations or a renderer JavaScript heap. Native CDP caps take effect in rebuilt CEF packages; managed guards also protect binding-owned copies when an older shim is loaded.

Boot-image version persistence and explicitly authorized macOS update elevation are existing product contracts. The supplied claims did not establish current vulnerabilities that justify silently removing those contracts. Historical policy claims are distinguished from current boundary failures in the table.

Implementation and assessment are tracked by `asura-iaqs`. Follow-up issues above remain open.
